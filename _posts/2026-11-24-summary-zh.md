从零开始构建的新浏览器引擎 Ladybird 已达到 alpha 阶段，目前可在 macOS 和 Linux 上使用。用户报告称，其在各种网站上的渲染兼容性出奇地好。 这是一个重要的里程碑，因为浏览器引擎市场由少数几个引擎（Blink、WebKit、Gecko）主导，一个真正独立的引擎可以促进竞争、多样性以及网络标准和隐私方面的创新。它还提供了一个不与谷歌广告业务挂钩的替代方案。 Ladybird 使用自己的渲染引擎，与现有引擎不共享代码，并由一个 501(c)(3) 非营利组织支持。早期用户注意到一些小问题，如滚动略有卡顿，并且有关于改进指纹识别抵抗和细粒度权限的讨论。

## [Anthropic 形式数学仓库声称在所有域上 VP ≠ VNP](https://github.com/anthropics/formal-math/tree/main/vp-vnp) ⭐️ 9.0/10

Anthropic 在 GitHub 上的形式数学仓库发布了一篇论文，声称复杂性类 VP 和 VNP 在所有域上都不相等。该成果是 AI 辅助形式数学工作的一部分，引发了关于 P vs NP 进展以及 AI 在数学研究中作用的激烈讨论。 如果正确，VP ≠ VNP 将是代数复杂性理论中的重大突破，类似于在代数领域解决 P vs NP 问题。它还展示了像 Lean 这样的 AI 辅助形式验证工具在解决深层数学问题方面日益增强的能力。 论文明确指出，尚未分析该结果与相对化和代数化的关系，而这些是复杂性理论中的标准障碍。这一警告表明，该证明可能需要进一步审查，以确保它不会落入已知的不可能性陷阱。

hackernews · mikeryan52 · 11月23日 22:09 · [社区讨论](https://news.ycombinator.com/item?id=50620102)

**背景**: VP 和 VNP 是类似于 P 和 NP 的代数复杂性类，使用计算多项式的算术电路来定义。VNP 包含像积和式这样的多项式，而 VP ≠ VNP 将意味着积和式无法由多项式大小的算术电路计算，这与著名的 P vs NP 猜想相呼应。使用 Lean 等工具进行形式验证可确保证明经过机器检查的正确性。

## [智谱 AI 发布 GLM-5.4，首个面向编程的循环 Transformer 模型](https://z.ai/blog/glm-5.4) ⭐️ 8.0/10

智谱 AI 发布了 GLM-5.4，这是其首个面向通用编程的循环 Transformer 模型，并附有详细的技术文档。该模型目前仅通过智谱的 Coding Plan 提供，该计划提供的 API 密钥可访问新模型。 GLM-5.4 代表了向循环 Transformer 架构的重要转变，这一方向可能通过跨多个计算步骤重用权重来提高推理效率。智谱的透明度与许多西方 AI 公司的封闭做法形成对比，为最先进 LLM 的未来提供了洞见。 循环 Transformer 在多次迭代中重用同一组权重，可能减少推理过程中的内存带宽瓶颈。然而，社区成员指出 GLM-5.4 表现出“马拉松式思考”，过度自我怀疑，导致完成时间比前沿模型更长。

hackernews · foohis · 11月23日 10:06 · [社区讨论](https://news.ycombinator.com/item?id=50609685)

**背景**: Transformer 架构在 2017 年的论文《Attention Is All You Need》中提出，通过多层权重处理数据，推理时每层计算一次。相比之下，循环 Transformer 多次迭代相同的层，类似于展开 for 循环，可以优化内存带宽——这是 LLM 推理的关键瓶颈。

## [OpenAI 与 Cisco 推出 Shirudo：开源 Linux 运行时助力补丁保护](https://openai.com/index/introducing-shirudo) ⭐️ 8.0/10

OpenAI 与 Cisco 发布了 Shirudo，这是一个开源 Linux 运行时，帮助团队在推出补丁时保护正在运行的系统。该项目名称在日语中意为“盾牌”，利用 eBPF 技术在不重启服务的情况下阻止漏洞利用。 这家领先的 AI 公司与主要网络设备供应商之间的合作，解决了一个关键的安全缺口：补丁发布与部署之间的窗口期，系统仍处于易受攻击状态。通过提供基于 eBPF 的开源防护盾，Shirudo 可以降低管理 Linux 集群的组织的停机时间和风险，尤其是当代理式 AI 系统越来越多地与基础设施交互时。 Shirudo 利用 eBPF 技术，允许在操作系统内核中运行小型自定义程序而无需修改内核源代码，从而实现实时漏洞缓解。该公告内容简短，缺乏技术细节，如支持的内核版本、性能开销或与现有补丁管理工作流的集成细节。

rss · OpenAI Blog · 11月23日 21:20

**背景**: Linux 内核实时补丁是一种无需重启即可将关键安全补丁应用于运行中内核的技术，可最大限度地减少停机时间。eBPF（扩展伯克利包过滤器）是一种 Linux 内核技术，允许开发者在内核中运行沙盒程序以安全地扩展功能，常用于网络、可观测性和安全领域。Shirudo 基于这些概念，在补丁推出期间提供保护层，可能弥合漏洞披露与完全打补丁之间的差距。

## [Codex2api 供应链攻击：后门版本泄露密钥](https://github.com/WormW/codex2api-incident-2026-11) ⭐️ 8.0/10

Codex2api 的作者账号被黑，攻击者绕开 main 分支推送 tag，构建出带后门的版本 v3.1.11。该版本去掉了鉴权，导致无密码远程执行命令，同时有 workflow 将同账号下至少 21 个仓库的 16 个 GitHub Actions secrets 外传。 这是一起针对真实项目的具体供应链攻击，任何安装或更新了 3.1.10–3.1.12 版本的用户必须立即停用、回退到 3.1.9，并轮换所有相关密钥，包括 GitHub token、SSH key、数据库凭证和 DeepSeek API 密钥等。该事件凸显了维护者账号被黑的风险，以及开源 CI/CD 流程中分支保护和密钥管理的重要性。 攻击者直接推送 tag 绕过了 main 分支，这表明分支保护规则可能未覆盖 tag，或者被黑账号拥有较高权限。后门版本移除了鉴权，相当于允许未认证的远程命令执行，并且恶意 workflow 被用于从多个仓库外传密钥。

## [黎曼猜想「AI 证明」被指空转，作者承认代码满是垃圾](https://x.com/i/web/status/2124987173439209561) ⭐️ 8.0/10
